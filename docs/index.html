L

LSH — Locality Sensitive Hashing

Hash-based Approximate Nearest Neighbor search

1 Input

Ο LSH δέχεται το dataset, τα queries και τις παραμέτρους που ελέγχουν τη συμπεριφορά του.

ΠαράμετροςΠεριγραφήDefault
-dDataset (MNIST: 60.000×784, SIFT: 70.000×128)—
-qQuery vectors—
-kΑριθμός hash functions ανά πίνακα10
-LΑριθμός hash tables30
-wΠλάτος παραθύρου1.5
-NΑριθμός γειτόνων προς επιστροφή5
-RΑκτίνα range search2000 (MNIST) / 2.0 (SIFT)
-type"mnist" ή "sift"—

Βήματα φόρτωσης

  1. Parse argvΑνάγνωση όλων των flags από τη γραμμή εντολών.
  2. Φόρτωση datasetΚλήση return_mnist_data() ή return_sift_data().
  3. Φόρτωση queriesΚλήση return_mnist_queries() ή return_sift_queries().
  4. Μετατροπή float → doubleΌλοι οι αλγόριθμοι δουλεύουν με vector<vector<double>>.

2 Build Phase — Πώς χτίζεται το index

  1. Initialize(dataset_n)Δημιουργία RNG με seed και κατανομών: normal(0,1), uniform(0,w), uniform_int(1, M-1).
  2. Δημιουργία τυχαίων componentsΓια κάθε table i = 0..L-1 και κάθε hash function j = 0..k-1: τυχαίο διάνυσμα v[i][j] (διάστασης dim), μετατόπιση t[i][j], συντελεστής r[i][j].
  3. Υπολογισμός tableSizetableSize = max(1, dataset_n / 4) — 25% του dataset. Σταθερό M = 4294967291 (πρώτος ~2³²-5).
  4. CreateHashTables(dataset)Για κάθε point j και κάθε table i: υπολογισμός hash value και εισαγωγή στο αντίστοιχο bucket.
  5. CreateHFun(point, tableIndex)Ο πυρήνας του LSH: υπολογισμός k partial hashes και συνδυασμός τους σε ένα ID.

Η hash function βήμα-βήμα

// Για κάθε μία από τις k hash functions:
dot_product = v[h] · point
if (dot_product > INT_MAX || dot_product < INT_MIN) exit;
numerator = dot_product + t[h]
h_h = floor(numerator / w)

// Συνδυασμός σε ένα ID:
ID = 0
for h = 0..k-1:
    hu = (h_h mod M + M) mod M       // θετικό modulo
    ID = (ID + r[h] * hu mod M) mod M
return ID mod tableSize
Σημείωση: Το overflow check προστατεύει από ακραίες τιμές του εσωτερικού γινομένου, που θα προκαλούσαν undefined behavior.

3 Query Phase — Πώς βρίσκεις τους γείτονες

Προσεγγιστική αναζήτηση (ANN)

  1. candidate_set = κενόΧρήση unordered_set<int> για αποφυγή διπλότυπων.
  2. Για κάθε table i = 0..L-1Υπολογισμός query_hash = CreateHFun(q, i).
  3. Union των bucketsΑν το bucket υπάρχει, insert όλα τα σημεία του στο candidate_set.
  4. Υπολογισμός αποστάσεωνΓια κάθε candidate: euclidean_distance(q, dataset[c]).
  5. Sort & Top-NΤαξινόμηση κατά αύξουσα απόσταση, διατήρηση N πρώτων.

Ακριβής αναζήτηση (ENN)

Brute force σε όλο το dataset — υπολογισμός απόστασης από κάθε point, sort, resize(N).

4 Μετρικές — AF, Recall, QPS

Average Factor (AF)

AF = aNN[0].second / eNN[0].second

Λόγος της προσεγγιστικής απόστασης προς την ακριβή. Τιμή κοντά στο 1.0 = καλή προσέγγιση.

Recall@N

recall_hits = 0
for exact in eNN:
    for approx in aNN:
        if exact.id == approx.id:
            recall_hits++
            break
recall = recall_hits / eNN.size()

QPS (Queries Per Second)

start_all = chrono::high_resolution_clock::now()
// ... επεξεργασία όλων των queries ...
end_all = chrono::high_resolution_clock::now()
total_time = duration<double>(end_all - start_all).count()
qps = queries.size() / total_time

Τελικές μετρικές (μέσοι όροι)

Total Average AF = total_Average_factor / valid_q Total Average Recall@N = total_recall / valid_q QPS = queries.size() / total_time Average Approximate Time = total_atime / valid_q Average Exact Time = total_etime / valid_q

Hypercube — Random Projection

Προβολή σε υπερκύβο με Hamming distance traversal

1 Input

ΠαράμετροςΠεριγραφήDefault
-kprojBits του υπερκύβου (αν 0 → auto)14
-MΜέγιστος αριθμός υποψηφίων10
-probesΑριθμός κορυφών προς εξέταση2
-wΠλάτος παραθύρου4.0
-NΑριθμός γειτόνων1
-RΑκτίνα range search2000 / 2.0

2 Build Phase

  1. hypercube_dimension(dataset, kproj)Αν kproj > 0 → χρήση του. Αλλιώς: d' = max(log₂n − rand_offset, 1) με rand_offset ∈ [1,3].
  2. initialize_LSH_func(dataset)Δημιουργία d' τυχαίων διανυσμάτων v και μετατοπίσεων t.
  3. project_to_hypercube(dataset, point)Για κάθε i: dot = v[i]·point, num = floor((dot + t[i]) / w), bit = num % 2 == 0 ? '0' : '1'. Το αποτέλεσμα είναι string από bits.
  4. build_index(dataset)Για κάθε point: υπολογισμός vertex, h_map[vertex].push_back(i).

3 Query Phase

  1. Project query → vertexquery_vertex = project_to_hypercube(q).
  2. Hamming distance traversalΓια hamming_dist = 0..kproj: εξέταση κορυφών με αυτή την απόσταση.
  3. M / probes limitΣταματάει όταν ελεγχθούν M σημεία ή probes κορυφές.
  4. Top-NSort candidates και επιστροφή N πρώτων.

vertices_at_hamming_dist

// Δημιουργία όλων των κορυφών με target_dist διαφορές
mask = [true × target_dist, false × (n - target_dist)]
do {
    new_vertex = vertex
    for i: if mask[i]: flip bit i
    res.push(new_vertex)
} while (prev_permutation(mask))

4 Μετρικές

Ίδιες με LSH: AF, Recall@N, QPS, χρόνοι.

5 Output

Hypercube Query: 0 Nearest neighbor-1: ... ... FINAL METRICS: Total Average AF: ... Total Average Recall@N: ... QPS: ... Average Approximate Time: ... Average Exact Time: ...

IVFFlat — Inverted File Flat

k-means clustering με ακριβή υπολογισμό αποστάσεων

1 Input

ΠαράμετροςΠεριγραφήDefault
-kclustersΑριθμός clusters (script: 256)14
-nprobeΑριθμός clusters προς εξέταση2
-NΑριθμός γειτόνων1
-RΑκτίνα range search2000 / 2.0

Dimension: (type == "mnist") ? 784 : 128

2 Build Phase

  1. Initialize(dataset_n)centroids.resize(kclusters) και cluster_members.resize(kclusters).
  2. CreateClusters(dataset)Επιλογή kclusters τυχαίων unique indices ως αρχικά centroids.
  3. k-means iterations (0..19)Assign: κάθε point στο κοντινότερο centroid. Update: new_centroid = mean των σημείων. Early stopping όταν iteration > 5 && !changed.
  4. find_nearest_centroid(p)Γραμμική αναζήτηση σε όλα τα centroids με euclidean_distance.
  5. find_nearest_centroids(p, nprobe)Sort όλων των αποστάσεων, επιστροφή nprobe πρώτων.

3 Query Phase

  1. find_nearest_centroids(q, nprobe)Βρίσκουμε τα nprobe κοντινότερα centroids.
  2. Union των cluster_membersΣυλλογή όλων των σημείων από τα επιλεγμένα clusters σε έναν vector candidates.
  3. Max-heap top-NΧρήση priority_queue<pair<double,int>>. Αν heap.size() < N → push. Αλλιώς αν dist < top → pop & push.
  4. Sort & ReverseΜεταφορά σε vector, sqrt, reverse για αύξουσα σειρά.
최적화: Το max-heap δίνει O(n log N) αντί για O(n log n) του πλήρους sort.

4 Μετρικές

Ίδιες με LSH, συν το Silhouette Score για αξιολόγηση της ποιότητας του clustering.

Silhouette Score

// Sample 100 τυχαία σημεία
a_i = mean απόσταση από ίδιο cluster
b_i = min mean απόσταση από άλλα clusters
silhouette[i] = (b_i - a_i) / max(a_i, b_i)
return mean(silhouette)

IVFPQ — Product Quantization

Συμπιεσμένη αναπαράσταση με Look-Up Tables

1 Input

ΠαράμετροςΠεριγραφήDefault
-kclustersΑριθμός IVF clusters50
-nprobeΑριθμός clusters προς εξέταση5
-MΑριθμός subspaces (πρέπει dim % M == 0)16
-nbitsBits ανά subspace8
-NΑριθμός γειτόνων1

2 Build Phase

  1. IVF Clusteringk_means(kclusters, 100, 1e-4, 42) → ivf_labels, ivf_centr.
  2. Inverted ListsΓια κάθε point i: inv_list[ivf_labels[i]].push_back(i).
  3. Υπολογισμός Residualsresidual[i] = point[i] - ivf_centr[ivf_labels[i]].
  4. PQ TrainingΓια κάθε subspace i: k-means σε 2^nbits clusters → pq_codebook[i].
  5. EncodingΓια κάθε point: best_code = argmin_c euclidean_distance(sub_vec, codebook[j][c]) → pq_code[i][j].

3 Query Phase

  1. find_nearest_centr(q, nprobe)Εύρεση nprobe κοντινότερων IVF centroids.
  2. Για κάθε centroid: build_LUTquery_residual = q - ivf_centr[c]. Για κάθε subspace: LUT με 2^nbits entries.
  3. Υπολογισμός απόστασης μέσω LUTdist += LUT[i][pq_code[point_id][i]] για i = 0..M-1 — μόνο M προσθέσεις!
  4. Sort & Top-NΤαξινόμηση και διατήρηση N πρώτων.
Key insight: Αντί για M×sub_dim πολλαπλασιασμούς, ο IVFPQ κάνει M προσθέσεις — τεράστια επιτάχυνση.

4 Μετρικές

Ίδιες: AF, Recall, QPS, χρόνοι.

Στο range search χρησιμοποιείται approx_R = R * 1.5 για αντιστάθμιση της προσεγγιστικότητας.

5 Output

IVFPQ Query: 0 Nearest neighbor-1: ... distanceApproximate: ... distanceTrue: ... R-near neighbors: <id1> <id2> ------------------- FINAL METRICS: Total Average AF: ... Total Average Recall@N: ... QPS: ... Average Approximate Time: ... Average Exact Time: ...

⚖️ Trade-off Ανάλυση

Ακρίβεια vs Ταχύτητα

  • IVFFlat:Υψηλή ακρίβεια + υψηλή ταχύτητα = Καλύτερος overall.
  • Hypercube:Χαμηλή ακρίβεια + υψηλή ταχύτητα = Καλός για γρήγορες απαντήσεις.
  • IVFPQ:Μέτρια ακρίβεια + χαμηλή ταχύτητα = Δεν συνιστάται.
  • LSH:Χαμηλή ακρίβεια + μέτρια ταχύτητα = Περιορισμένη χρήση.
Βέλτιστη επιλογή overall: IVFFlat — κερδίζει σε όλες τις κατηγορίες εκτός από απόλυτη ταχύτητα.
Προσοχή: Οι default παράμετροι ίσως δεν είναι βέλτιστες για LSH & Hypercube — χρειάζεται parameter tuning.

Ανά περίπτωση χρήσης

🎯 Για Υψηλή Ακρίβεια

IVFFlat — σχεδόν τέλειος recall (0.98 MNIST, 0.89 SIFT) με καλή ταχύτητα.

⚡ Για Μέγιστη Ταχύτητα

Hypercube — 760 QPS στο SIFT, αλλά με θυσία ακρίβειας.

⚖️ Για Ισορροπία

LSH — ικανοποιητική ταχύτητα και AF, αλλά χαμηλή ακρίβεια.

❌ Δεν Συνιστάται

IVFPQ — χαμηλή ταχύτητα + χαμηλή ακρίβεια + υψηλό AF.

Παρατηρήσεις

  1. Το SIFT φαίνεται καλύτερα βελτιστοποιημένοΠολύ υψηλότερα QPS από το MNIST.
  2. Οι default παράμετροι δεν είναι βέλτιστεςΧρειάζεται tuning για LSH & Hypercube.
  3. Χρειάζεται brute force σύγκρισηΓια απόλυτα αξιόπιστα συμπεράσματα.
